# 学员档案「三格」+ 个人资料（姓名/学科/校区）· 方案与实做记录

> 用户 2026-10 提的（逐字）：
> 「在学生档案这部分，我想改一些东西，比如第二格我想把校区改为学校，第三格我想把教师改为学管师。
> 改的原因是这样的：每一个老师使用时，自己保存的学生档案要做区分，一个老师一般只教一门课，
> 所以第三格的学科教师就不用填写了，但是每一个学生又对应有独立学管师，教师通常与学管师进行沟通学情，
> 所以需要加一个标记，另外老师基本上是全职教授，固定校区，所以校区那栏变化不大，
> 不妨改为学生的信息部分较好。」
>
> 「我们能否在注册页面后加入填写信息模块，信息填写就需要填写姓名、科目、校区等你认为必要的，
> 然后未来我们首页这个部分就显示这几个主要信息，然后导出来的档案文件什么的就可以从这里提取信息了，
> 然后别忘了再加入一个修改信息的功能即可」
>
> 「管理员在管理后台的开通会员的页面最好能看的是老师姓名和所校区等基本信息，
> 然后邮箱放到现在的那一堆字符码的部分，这一堆字符码是啥我也不知道，可以直接隐藏掉。」
>
> 用户已拍板：**1A（落款存服务器）+ 2A（落款即教师身份、旧记录不动）+ 分三次做**；
> 注册引导**可跳过**；学科用**下拉**；「校区」= **机构校区**（与学生的「学校」不是一回事）。

## 二、第二批（待做）：个人资料（姓名 / 学科 / 校区）

### 2.1 为什么它比"落款"那个方案更好

用户原想"落款改成填写方式 + 记住上次用的落款和学科"；后来提出"注册后填个人信息"。
**后者是前者的超集**，而且把散落的个人信息收成**一个来源**：

| 现在（散落） | 改后（一个来源） |
|---|---|
| feedback 的「落款」被硬写成「数学郭老师」（`feedback.html` L3311） | 落款默认 = **学科 + 姓名**（从资料拼出来，仍可临时改） |
| 试卷分析 / 数学方案里 **4 处** `\|\| '郭庆杰'` 兜底，会印进导出的 Word | 从资料取；没填资料时才退回现在的行为 |
| 两个工具页的标题/页头写死「· 郭庆杰」 | 从资料取 |
| 学科默认 `math` / `数学` 写死 | 从资料取 |
| 「任课教师默认就是自己」（用户的话） | 从资料取 |

### 2.2 计划

| 项 | 内容 |
|---|---|
| 存储 | **新表 `user_profiles`**（每人一行：`user_id` / `name` / `subject` / `campus` / `updated_at`）+ **迁移 `0021`**（要用户在 Supabase 跑一次） |
| 注册后引导 | `/welcome`（**可"以后再说"**，不挡注册）；没填的话首页一直提示补 |
| 首页账号卡 | 显示 **姓名 · 学科 · 校区** + 「**修改信息**」按钮（`/account/profile`） |
| 工具读取 | 扩展**已有的** `/api/feedback/data` 的 GET 返回里加一个 `profile` 段（三个工具都已经在调它，不必新开接口）；数学方案的档案保存也在走 `/api/students` |
| 清掉写死 | `public/tools/paper-analysis/js/narrator.js`（2 处）、`report-docx.js`、`report-template.js`、`app.js`（4 处）、两个 `index.html`/`feedback.html` 的标题与页头 |
| 兜底 | **读不到资料/表还没建 ⇒ 行为与现在完全一致**（不会变空、不会坏）。这条必须有断言钉住 |

### 2.3 ⚠️ 迁移没跑时也要能用（重要设计）

`user_profiles` 表不存在时：
- **读**：整段跳过，工具拿不到资料 ⇒ 走兜底（默认落款/原来的字面量）；
- **写**：明确提示"资料表还没建，请在 Supabase 执行 `0021`"（照功能开关表的先例：**点名文件名**）。

这样"先推代码、后跑迁移"不会坏 —— 用户跑完迁移那一刻功能自动生效。
