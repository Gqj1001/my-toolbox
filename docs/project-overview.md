## 一、这是什么

| 项 | 内容 |
|---|---|
| 网址 | **010034.xyz** |
| 是什么 | 一个**个人教学工具平台**——给老师用的小工具集合，不是给学生做题的 |
| 给谁用 | 面向**高中数学老师**（未来扩到全学科，见第七节） |
| 技术 | Next.js（网站框架）+ Supabase（登录与数据）+ Vercel（部署上线） |
| 代码在哪 | `D:\my-website\my-toolbox`（网站） |

**一句话理解**：网站负责「登录、收费、目录」，具体的工具是独立的网页，被网站「嵌」进页面里显示。

⚠️ **重建数据库会失败**：`tools` 表和 `user_roles` 表里，**有一部分结构只存在于线上**，
代码仓库里根本没有对应的建表语句（详见第三节末「三个隐患」）。**不要试图用仓库的 SQL 重建数据库。**

### 学生档案现在有三个工具在共用（2026-10 起）

`feedback_students` / `feedback_history` 这两张表**名字带 feedback，但已经是全站统一的学生档案**
（`0014_students_unified_fields.sql` 给它们补了公共字段 + `extra jsonb`）。
写入有**两个入口，语义不同**，这是当前最容易踩的地方：

| 入口 | 语义 | 谁在用 |
|---|---|---|
| `POST /api/feedback/data`（老） | **整行覆盖**（PostgREST upsert，没带的列写 NULL） | feedback 工具（**一行未改**，正常工作） |
| **`POST /api/students`（新，0015 起）** | **合并语义**（先读旧行，只覆盖传了的字段） | paper-analysis / math-plan（都已接入） |
| `POST /api/students { op:"manual" }`（第十四批） | **新增一条记录**（老师手动补录的成绩） | 学员档案页 `/dashboard` 的「📝 补录一次成绩」 |

> ⚠️ **为什么必须有两个入口**：0014 之后同一行装三个工具的字段。
> 用老入口保存会把**别家工具的字段静默清空** —— 例如 math-plan 存的
> `grade`/`campus`/`extra` 会被 feedback 的一次「保存档案」抹掉。
> 新入口靠「先读旧行再合并」解决，并有测试钉住
> （`tests/students-unified.test.mjs` 的「合并③」组）。
> 将来若要统一，应当让老入口也走 `upsertStudent()`，而不是各写一套。

> ✅ **`extra` 现在也是服务端按键合并了（2026-10 第二批）**：写入前服务端先读回旧 `extra`、
> 展开、再盖上本次传的键 —— 所以**任何工具少写一句都不会踩到别人**。规则三条：
> ① 同名键**新值赢**；② 别的工具的键**原样保留**；
> ③ `extra` 里某个键传 `null` = **删掉那个键**（而「整个 `extra` 传 `null` / 没传」= 沿用旧值）。
> 实现是 `src/lib/feedback-db.ts` 的 `buildStudentRow()` → `mergeExtra()`；
> 证据是 `tests/students-unified.test.mjs` 的「阶段5」组与
> `tests/math-plan-students.test.mjs` 的「extra 互不踩③」。
>
> > ⚠️ **在此之前那是个真 bug，不是"将来会咬人"**：`extra` 传了就是整块替换，
> > 而 `paper-analysis` 的 `CLOUD_STORE.saveStudent()` **并没有**先读旧值（它只发 `{cls}`）——
> > 所以「先在 math-plan 存了 phase/book/exam，再到 paper 点一次保存」时，那三个键**当场消失**。
> > 工具页那句「先读旧值」**仍然保留**（服务端合并是**兜底**，不是替代；两边都做，结果一致、幂等），
> > 但**已经不再依赖它**了。
> >
> > 💰 **代价（用户选的）**：合并前改成**直读最新行**（不再用 25 秒缓存）——
> > 每次「保存档案」多一次 Supabase 往返。理由：按键合并的正确性完全依赖旧值是最新的；
> > 保存是低频动作，换来的是不丢数据。

字段归属：公共列 = 姓名 / 年级 / 科目 / 老师 / 称呼 / 态度 / 校区 / 学管师 / 班级 / 性别；
**工具专属字段进 `extra` jsonb**（paper → `cls`；math-plan → `phase/book/exam`），
所以**以后加新工具不需要改表结构**。

> ⚠️ **成绩走的是"记录"表，不是 `extra`（第十四批记录在案）**：
> `feedback_history` 的 `(score, full_score, date, title, tool)` 是分数的**权威形态** ——
> 试卷分析自动存的、和老师在档案页**手动补录**的（`tool='manual'`），在报表里长得一模一样。
> 学情分析的「成绩趋势」**扫全部带分数的记录、不挑工具**，所以补录一条**自动**进趋势与 AI 报告；
> 反过来，**千万别把成绩塞进 `extra`**（那是"学生是谁"的身份字段，且进不了趋势）。

> ⚠️ **math-plan 只存「学生是谁」，不存「这一次方案」**（用户明确要求）：
> 分数 / 目标分 / 课时 / 频次 / 薄弱模块 / 已完成模块 / 备注 **都不进档案** ——
> 那些属于某一次方案；存进档案会「换个学生做方案，把上一位的分数写成他的」。
> 测试里有一条**双重防护**：既点名查这些键，又断言 `extra` 里**没有数字型值**
> （身份字段全是字符串，出现数字基本就是泄漏）。见 `tests/math-plan-students.test.mjs`。
> ⚠️ math-plan **目前不写任何历史记录** —— `feedback_history.tool` 的 CHECK 只允许
> `('feedback','paper')`，要加 `math-plan` 必须先跑一条迁移。

> ⚠️ 合并语义有一个必须知道的细节：`extra` 是 `not null`，
> 所以「没有值」时是**省略这个键**（让数据库默认 `{}` 生效），**绝不能写 `null`**。
> 写 null 会撞 23502 约束错误 —— 而且症状很迷惑：**新建**档案一律 500、**更新**已有档案却正常。
> 见 `src/lib/feedback-db.ts` 的 `buildStudentRow()`。

> ⚠️ **写档案前那次「读旧行」是严格读（2026-10 第四批）**：读失败 → **中止写入**，
> 接口返回 **503** +「读取档案失败，本次没有做任何修改，请重试。」
> 绝不退化成"没有旧行" —— 那会把**没传的列写成 NULL**（实测过：接口返回 `200 ok:true`，
> 而库里 `grade`/`campus` 已被抹成 null，属于**静默数据丢失**）。
> **读接口故意相反**（`getStudentsFresh()` 仍软降级、返回空、不 500）——
> 两种取舍不同，别为了"统一"把任何一边改掉。见 `StudentRowReadError` 的注释。

## 三、网站的公共设施（跟具体工具无关的部分）

### 1. 登录
用 **Supabase 的邮箱 + 密码**（有注册页、登录页、邮箱确认链接）；**没有**微信/QQ 等第三方登录。
没登录的人**什么页面都进不去**（连工具本身的网页文件也拦），送去登录页；登录后自动回到原来想去的页面。

**忘记密码 / 修改密码（2026-10 第十五批）**：

| 场景 | 入口 | 路径 |
|---|---|---|
| **忘记密码**（没登录也能用） | 登录页 →「用邮箱重置」 | `/forgot-password` 填邮箱 → 邮件链接 → `/auth/confirm`（换出会话）→ `/reset-password` 设新密码 |
| **修改密码**（登录后用） | 个人中心的会员卡旁 →「修改密码」 | `/account/password`（要填**当前密码** + 新密码两遍） |

- ⚠️ **`/forgot-password` 必须是公开路径**（`src/proxy.ts` 的 `PUBLIC_PATHS`）——
  忘了密码的人**恰恰是登不进来的人**，不放行就是死循环。
  **`/reset-password` 故意不公开**：走到那里的人一定已经由邮件链接换出会话了。
- ⚠️ **改密码必须先验当前密码**（用旧密码再登录一次，不依赖 Supabase 后台那个
  `..._REQUIRE_CURRENT_PASSWORD` 开关）——老师常在公共电脑上登录着。
  只有**重置流程**（表单里带隐藏字段 `reset=1`）跳过这一步，否则刚忘记密码的人会被要求填旧密码（死锁）。
- ⚠️ **要你在 Supabase 配一次**：Authentication → URL Configuration 的 **Redirect URLs**
  里加 `https://010034.xyz/auth/confirm` 与 `http://localhost:3000/auth/confirm`
  ——**不加的话重置邮件发不出去**（Supabase 拒绝跳到白名单外的地址）。详见 `docs/password-reset-plan.md` §3。
- ⚠️ **邮件链接的会话在 URL 的 `#` 片段里（2026-10 第十六批修的 bug，务必记住）**：
  Supabase 现在跳回来的是 `…/auth/confirm?next=/reset-password#access_token=…`，
  而 **`#` 永远不会发给服务器**。所以 `/auth/confirm` **必须是客户端页**
  （`src/app/auth/confirm/page.tsx` + `src/components/auth-confirm-client.tsx`，
  解析在纯函数 `src/lib/auth-callback.ts`）—— 它原来是**服务端路由**，
  只能读 `?token_hash=`，于是**什么都读不到 → 一律跳登录页**（症状：点重置链接看到登录界面）。
  ⚠️ 失败时页面上会给中文出路再跳 `/login?error=…`，**不要把上游英文错误甩给老师**。
  `tests/password-flows.test.mjs` 有一条**真浏览器**断言钉住这一跳（片段会话 → `/reset-password`）。
- 报错中文翻译与密码规则各自**只有一个来源**：`src/lib/auth-errors.ts`、`src/lib/password-policy.ts`。
  （⚠️ 同步的纯函数**不能**放在 `"use server"` 文件里 —— 那种文件每个 export 都必须是 async，
  否则构建直接报 `Server Actions must be async functions`。）

### 2. 会员系统
**「免费 / 会员 / 封禁」不是三个并列等级，而是两条轴**（这点最容易看错）：

| 轴 | 取值 | 存在哪 |
|---|---|---|
| 会员等级 | `免费版`（free） / `会员版`（vip） | `user_roles` 表的 `plan` |
| 账号状态 | `正常`（active） / `已封禁`（banned） | `user_roles` 表的 `status` |
| 到期时间 | 日期 | `user_roles` 表的 `expires_at` |

- **算不算有效会员** = 等级是会员 **且** 状态正常 **且** 到期时间还没过。三条缺一条就不是。
- **封禁**：状态改成「已封禁」后，整个网站都进不去，一律跳到 `/banned` 提示页。
- **开通方式**：**没有在线支付**。非会员点会员工具 → 跳到 `/upgrade` 页面 → 提示「联系管理员开通」。
  真正开通是管理员在后台点按钮。
- 没在 `user_roles` 里建过行的人，**一律当免费用户**处理。
- **新注册自动送 15 天会员**（2026-10-20 新功能；迁移 `0023` **已执行并验证通过**）：
  在 `auth.users` 新增一行时，由数据库触发器往 `user_roles` 插一条
  `plan=vip / status=active / expires_at=now()+15 days`。所有注册路径都覆盖（不靠前端）。
  只在**新用户插入**时动手，且 `on conflict (user_id) do nothing` ⇒ **不会覆盖**管理员之后的手动开通/取消/封禁；
  **不回溯**已注册的老用户。设计与验证见 `docs/auto-trial-vip-plan.md`。

### 4. 权限判断逻辑（一个工具能不能打开）

```
用户打开 /tools/某工具

  → 状态是已封禁？     → 送去 /banned
```

## 五、两个 DSH 会话的分工

这个项目**同时开两个 DSH 会话**，各管一块，**互不越界**：

| 会话 | 管什么 | 主要动的文件 |
|---|---|---|
| **工具会话** | 工具**本身**（工具怎么算、怎么导 Word、AI 怎么写） | `public/tools/` 下的东西、`src/app/api/**` 的 AI 接口 |
| **网站会话** | 登录、会员、路由、目录、权限、后台 | `src/app/` 页面、`src/lib/`、`src/components/`、`supabase/migrations/` |

**两条约定**：① **不跨会话改对方的文件**——需要对方改就写清楚需求交过去，别自己动手；
② **不确定归谁时先问用户**，不要猜。理由：两边改的是同一批功能的两个层面（工具"算得对不对"
vs 网站"谁能进得来"），混着改容易一边修好另一边弄坏。所以 `public/tools/*.html` 是**工具本体**
（工具会话地盘），网站会话改的是**嵌它的那层壳**。

### 客户端缓存（IndexedDB，2026-10 新增）

服务端缓存（30 秒 / 10 分钟 TTL）只能省「同一实例短时间内重复查库」；
老师**两节课之间**再打开，早就过了 TTL，还是要等一次完整的跨洋往返。
所以把**全局静态数据**（分类 / 教材 / 章节 / 短语 / 当前维度关键词）缓存在**用户设备**上：

- 打开工具页先读本机缓存 → **立即出内容**（不再对着骨架屏等），同时**照常**打一次数据接口核对；
- 核对回来若与已显示的内容**逐字节相同** → 一行 DOM 都不动（不闪烁）；不同 → 静默替换；
- **学生档案与反馈历史绝不缓存**（红线，白名单 `CACHEABLE_KEYS` 从结构上排除）；
- 服务端随响应下发 `dataVersion`，变了就把本地缓存整批作废；
- 缓存超过 24 小时且没能核对成功 → 顶部明确提示「数据可能不是最新」。

> ⚠️ 唯一的取舍：版本号只有真实响应里才有，所以首屏那一刻**无法提前**知道缓存是否过期，
> 会先显示一瞬旧内容；核对发现变了就立刻替换，并把提示语写成
> 「（此前显示的是本机缓存，服务端已更新，画面已刷新）」——显示过就要认。
> 想消掉这一瞬只能每次先问一次服务器版本号，那又变回一次跨洋往返，功能就白做了。
>
> 紧急关掉：工具页加 `?noclientcache=1`。**完整记录见 `docs/perf-notes.md` 六之五。**

> P2 的关键认识：**「每次都要冷启动」的根因不是 TTL 短，而是缓存 key 太细** ——
> 以前教材表 17 条 key、章节 64 条，每换一个「学段+科目+教材」组合就是全新 miss。
> 现在教材表只剩 **1 条** key、章节按「学段|科目」17 条，换组合不再冷。
>
> P3 的关键认识：**中间件每次带 cookie 的请求都要 2 次外网查询**（`auth.getUser` + `user_roles`），
> 而打开一个工具页中间件要跑 2–4 次 —— 这才是「进入 `/tools/feedback` 等 4.31 秒」的主因。
> 现在中间件也有了同款 30 秒缓存，可用环境变量 **`MIDDLEWARE_CACHE_TTL`** 控制
> （默认 30 秒；**设 `0` = 关闭**）。它**只管中间件**那一份，与页面侧各缓存各的（不同运行时，内存不共享）。
>
> P4 的关键认识：**启动流程里 `NEXT_MODE` 是纯本地判断，却还多打一次
> `/api/feedback/mode` 只为取 `isAdmin`** —— 而那字段就在 `/api/feedback/data` 的响应里。
> 删掉这一跳同时消除了「先渲染 localStorage 旧数据、2–3 秒后才切成云端」的闪烁。
> ⚠️ **取舍：云端首屏拉不到数据时不回退 localStorage**（宁可空着并明确报错）——
> 因为回退会让老师**拿旧数据生成反馈**，家长会收到错内容。

**详见 `docs/perf-notes.md`**（含「缓存命中时数据不为空」这条断言——缓存最危险的失效方式是**静默变空**，
不是变慢）。

## 九、登录：A-2 会话刷新策略（2026-10 **已收口** ✅）

用户反馈「**每次进网站都要登录**」。查下来**不是** session 存不住（cookie 有效期 1 年、
关浏览器再开仍登录、access token 会自动续期），而是**并发刷新被 Supabase 判成「token 泄露」→ 撤销会话**。

**真凶（2026-10 实测定位）**：`@supabase/auth-js` 的 `__loadSession()` 在 access token
剩 **< 90 秒**时会**自己**去刷新，而 `_refreshAccessToken()` 内部**还带指数退避重试**。
所以「每请求新建一个 client」的写法会炸出一串 `/auth/v1/token` ——
实测 8 个并发请求最多 **24 次**；重试过程中某次 `getUser()` 返回 `null`，用户就被送去登录页。
⚠️ **`autoRefreshToken: false` 挡不住它**（那个开关只管后台定时器）。

做法（`src/lib/session-freshness.ts`，**中间件与页面侧共用**）：**绕开 auth-js 管理会话**，
只拿它查库（RLS）——
- 够新（剩余 > 120 秒）→ **0 次外网**，只解码 JWT；
- 快过期 / 已过期 → 由**中间件**直连 `/auth/v1/token` 刷**一次**（单飞 + 结果缓存），
  写回响应 Cookie；校验也直连 `/auth/v1/user`（不用 `getUser()`）；
- 并让 auth-js **读不到**快过期的会话（`hideStaleSessionFromAuthJs`），
  这样它连刷新的机会都没有 —— 这是最终生效的那一刀。

| 场景 | 修复前 | 现在 |
|---|---|---|
| token 还剩 1 小时 | — | **0 次刷新** ✅ |
| token 只剩 3 秒（单请求） | 1 次 | **1 次** ✅ |
| **并发 8 个「快过期」请求** | **16 次** | **1 次** ✅ |

> **安全取舍（用户已确认）**：不逐请求确认「token 是否被吊销」，改为每个 token 生命周期确认一次；
> 改密码/主动吊销最多延迟到该 token 过期（≤1 小时）。**封禁不受影响**（走 `user_roles`，独立一条链）。
>
> ⚠️ **最容易改错的一处**：`hideStaleSessionFromAuthJs` **只过滤「读」**。
> 千万别顺手把 Cookie 的**写**（`setAll`）也去掉 —— 登录/注册/登出都靠它写会话，
> 本轮先写成空实现，结果**登录直接失效**（被 `admin-grant90` 与 `feedback-client-cache` 两个套件抓出来）。
>
> 完整记录（含被推翻的旧结论）见 `docs/perf-notes.md` **六之七**。

## 十一、给新会话的开工三步

1. **读本页** → 知道全局有什么、哪些是空壳、有哪些隐患。
2. **读 `docs/dsh-work-guide.md`** → 知道怎么跟用户配合（大白话、先给方案再动手、push 前停下），
   以及**本项目踩过的坑清单**（那节能省你几小时）；第 13 条是"初版功能一律配后台开关"的约定。
3. **读 `docs/next-session-todo.md`** → 知道下一轮该做什么（每条都有「为什么」和「怎么验」）；
   开头有一句"当前状态"摘要（测试规模、最近三批做了什么）。
4. **要动公司模板导出那摊事，先读 `docs/company-export-plan.md`**（方案 + 数据来源 +
   §8 一键关掉/彻底撤销 + §8.5 后台功能开关）。
5. **只读你要改的那一块的交接文档** → 改工具看 `math-plan-handoff.md` / `paper-analysis-handoff.md`；
   改网站层看本页第三、五节 + `README.md`。**动手前先确认**：这事归哪个会话？**改完本页要不要跟着改？**

> **最后一条规矩**：改完代码要顺手改文档。
> 本页、`next-session-todo.md`、`perf-notes.md` 都会**主动声称**某些数字与状态
> （比如「并发刷新 8–12 次」—— 现已收到 **1 次**；「已上线 X」）—— 那些数字一旦过时，
> 下一个会话就会被误导。**内容变了就顺手改这里。**
