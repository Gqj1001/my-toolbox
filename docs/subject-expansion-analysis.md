| 签字 | 教管主任 / 家长 | 附件3 四栏签字 |

所以"用附件3 导出"= 把同一批数据填进规范版 —— **我们的引擎方向本来就是对的**。

### 1.3 模块划分（物理）

**高中物理（高三全年，23 个模块，共 213h）**——注意它**不是按"力学/电学/热学"分大块**，
而是**按教材章节顺序**铺开，再用「一轮/二轮」标出阶段：

| 阶段 | 模块（时序） | 课时 |
|---|---|---|
| **一轮专题复习**（88 节 / 132h） | 运动的描述 3 → 匀变速直线运动 6 → 相互作用·力 6 → 运动与力的关系 9 → 抛体运动 6 → 圆周运动 4.5 → 万有引力与宇宙航行 6 → 机械能守恒定律 9 → 动量守恒定律 7.5 → 力学实验 4.5 → 光学 6 → 原子结构和波粒二象性 1.5 → 原子核 3 → 热学专题 9 → 机械振动、机械波 7.5 → 静电场及其应用 4.5 → 静电场中的能量 6 → 电路 6 → 电学实验 6 → 磁场 7.5 → 电磁感应 7.5 → 交变电流 6 | |
| **二轮大专题**（36 节 / 54h） | 力学专题 15 →（大专题训练和讲解…） | |

> ⚠️ **与数学的结构性差异**：数学的 `MODULES` 是**按"高一上/高一下/高二上/高二下"编排的知识模块**
> （41 个，每个 2 课时粒度、含 base/mid/hard 三层内容）；物理样例是**按教材章节 + 一轮/二轮阶段**，
> 每个模块 1.5–9 课时（**粒度粗得多**）。**这不是"换名字"就行的差异，是"编排轴"不同。**

**初中物理（初三全托，24 个模块，166.5h）**——同样是章节轴，但**分两段**：

| 阶段 | 模块 | 课时 |

| 学校同步（期末前，共 61.5h） | 第十三章内能 4.5 → 第十四章内能的利用 4.5 → 第十五章电流和电路 7.5 → 第十六章电压 电阻 7.5 → 十七章欧姆定律 10.5 → 十八章电功率 10.5 → 十九章生活用电 3 → 二十章电与磁 6 → 二十一章信息的传递 1.5 → 期末复习 6 | |
| 一轮复习（共 54h） | 声现象专题 1.5 →（后续专题…） | |

**个体短周期（张雨宸 九年级，13 章，28 小时）**：同样是章节轴，课时 0–4（**"第十三章内能 0 课时"** ⇒ 说明老师会把"已掌握/不讲"的章留 0，**引擎必须容忍 0 课时**）。

### 1.4 知识点怎么写（重要）

样例里「内容」一列**不是知识点名，而是"编号+标题"串**：

```
1.1质点　参考系  1.2时间　位移  1.3位置变化快慢的描述——速度  1.4速度变化快慢的描述——加速度
```

⇒ 这是**教材小节编号**（人教版必修一第 1 章）。对引擎的含义：

- **好消息**：附件3 的「具体知识点」列**本来就是任意文本**，塞进去完全没问题（实测已通过）；
- **要注意**：这类文本**很长**（我抽的样例单行 60–90 字），附件3 那一格会换行撑高；
  一行能装多少字要**在 Word 里看一眼排版**（我没渲染检查，建议你目测一份）。

### 1.5 课时分配惯例（可直接做成默认值）

| 学段/形态 | 总课时 | 频次 | 单模块课时 | 特征 |
|---|---|---|---|---|
| 高中 全年班组 | 213h | 4 次/周 | 1.5 – 15h | 一轮 132h + 二轮 54h；电磁学/热学/力学专题最重（7.5–15h） |
| 高中 阶段（新高二） | 28h | 2 课时/周 | 2 – 8h | 只做 4 章（机械能/动量/抛体/圆周/静电场） |
| 高中 高三班组 | 210h | 3–4 次/周 | 1.5 – 9h | 与全年近似，多一段「教学方法」 |
| 初中 初三全托 | 166.5h | 3 次/周 | 1.5 – 10.5h | 同步 61.5h + 一轮 54h；**电学最重（欧姆定律/电功率各 10.5h）** |

⇒ 现有 `buildLessons()`（`Math.round(h/2)` 拆成 2h 一次课）**逻辑上能用**，但会让"机械能守恒 9h"变成
5 行（4 个课型 + 1 个重复课型），和物理样例"一行 9h"的形状**不一样** —— 这是 **§3 的核心取舍**。

## 3. ⭐ 核心问题：把 math-plan 扩到物理，是"换配置"还是"改代码"？

### 3.1 直接回答

> **不是纯换配置，但也远不到"改逻辑"。**
> 是 **"抽一层配置 + 6 处小改"**：配置是大头（70%），代码是"把写死的东西改成读配置"（30%）。
> **引擎与导出（含公司附件3）一行都不用改** —— 这是本轮实测证实的。

理由（三条，都可验证）：

1. **引擎是通用的**：`report-template.js` 只认"占位符 → 值"，本轮用真实物理内容跑通（23 模块/147h）；
2. **决策逻辑是通用的**：`pickModules()` 的评分（档位×难度×标签×薄弱点）与学科无关，
   只是它读的 `MODULES` 字段要由科目包提供；
3. **写死的地方只有 6 处**（§2.2），全是"从常量改成读科目包"这类机械改法，
   **不动任何算法**。

### 3.2 但有一个**结构性取舍必须你拍板**（这是真正影响工作量的地方）

物理样例的进度表是「**一行 = 一个模块（章节），课时 1.5–15h**」；
而现有 math-plan 是「**一行 = 一次课（固定 2h）**，一个模块拆成 4–6 行（按课型）」。

| 选项 | 做法 | 好处 | 代价 |
|---|---|---|---|
| A | 保留 2h 一行的"次课"粒度，物理模块也按课型拆（概念与公式梳理 / 模型与方法 / **实验探究** / 题型突破 / 限时检测） | 与现有数学方案**形状一致**、老师已经熟悉；AI 改写/编辑/导出链全部照旧；不用改 `buildLessons()` | 附件3 里物理会**多出很多行**（213h ÷ 2 = 107 行），而老师样例只有 25 行 |
| **B ✅ 已选** | 改成「一行 = 一个模块」，课时直接写模块总课时 | 与老师样例**形状一致**（25 行，更像他们现在交的东西） | 要改 `buildLessons()` 与逐次课表 UI；**数学那边也会被迫变形状**（除非两套并存） |
| C | 两套并存：数学按次课、物理按模块 | 各自最优 | 两套代码路径 ⇒ 长期维护成本与"只测一半"的风险（本项目在"两个来源"上踩过） |

> **用户选了 B**（"模块属于更常见的要求"）。⇒ 新工具里：
> **一行 = 一个模块**，`课时数` 直接写该模块总课时（含小数，如 4.5h），**不再按 2h 拆次课**。
> ⚠️ 这条要在新工具里**从设计上就按 B 做**（不要抄 math-plan 的 `buildLessons()` 拆课逻辑）；
> 而公司附件3 的引擎本来就按"一行一模块 + 按模块合并"设计的，**正好对齐**（见 §0 实测）。

### 3.3 科目包（subject pack）长什么样

按 `docs/other-subjects-plan.md` §三 推荐的路线 2，辅导方案侧同样抽一层：

```
public/tools/math-plan/subjects/
├── math-senior.js      ← 现有数学那套原样搬进来（行为不变）
├── physics-senior.js   ← 本轮要写的
└── physics-junior.js   ← 初中物理（章节轴不同，是独立一套）
```

每个科目包导出同一组键：

```js
{
  key:'physics', stage:'senior', name:'物理', fullScore:100,
  bands:[{min:85,name:'冲高分'},{min:60,name:'提中档'},{min:0,name:'补基础'}],  // ← 替代 fmtScore 写死分段
  modules:[ {id, name, chapters, topic, term, lv, content, goal, tags, must?} ],
  sync:{ '高三':[...ids], '高二上':[...ids] },     // 编排轴（物理按册次/复习轮次）
  lessonTypes:[ … ],                                // 含「实验探究」
  bandText:{ 1:{…}, 2:{…}, 3:{…} },                 // 要给老师过的话术
  exams:[ … ]                                        // 只有试卷分析侧才用；辅导方案可留空
}
```

⚠️ **两个学段必须分开**（物理初中是"声/光/热/电与磁"章节轴，高中是"力/电/热/光/原子"，
**模块表不能共用**）—— 这与 `docs/other-subjects-plan.md` §E 的结论一致（2 学段 × N 学科）。

### 3.4 工作量与风险（诚实估计）

| 项 | 估 |
|---|---|
| 抽科目包 + 6 处小改（含"数学行为不变"的回归） | **1 – 1.5 天** |
