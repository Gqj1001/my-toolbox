> 用户 2026-10 交办的第一批（小优化），**三件都做完**，测试与变异自证见 §4。
> 本文档是这三件的方案与实做记录（用户休息期间做的，等他回来一起验收）。

## 件 1：识别失败**只重试那一页**

### 1.1 之前是什么样（先查证：**这条待办一直没做**）

`next-session-todo.md` 里从第六～七批就挂着这条"可选优化"，而 `app.js` 里那句注释
（"也让失败那页可单独重试"）**只是写着，代码没实现**。实际行为是：

```js
for (const 页 of pages) {
  const d = await apiFetch(...);
  if (!d.ok) throw new Error(...);   // ← 一页失败，整批作废
}
```

后果：20 页的扫描卷里第 7 页拍糊了，前面 6 页和后面 13 页的识别结果**全部丢掉**，
老师只能整份重传 —— 再花一次钱（视觉模型按页计费）。

### 1.2 两条管线都要改（别只改一条）

| 管线 | 接口 | 页数上限 | 失败单元 |
|---|---|---|---|
| **学科网报告截图 / 扫描版 PDF** | `POST /api/paper-analysis/vision-paper` | 10 | 每张图 / 每页 |
| **学校卷子（空白卷/批改卷/扫描版 PDF）** | `POST /api/paper-analysis/vision-paper-structure` | 20（10 页一批） | **页** |

### 1.3 做法

- **失败页只记下、不中断**：`visionFailed` / `schoolFailed`（`{index,label,message}`），
  成功页照常进结果；
- 状态区出现 **「🔁 只重试这 N 页」**（`btnVisionRetry` / `btnSchoolRetry`），
  并说明"其它页的结果已经保留，不用整份重来"；
- 重试**只重发失败页**：学校那条把"上次已成功页"一起带上、循环里按下标跳过它们
  （`toRetry` 集合）；图片那条只遍历 `visionFailed`；
- **失败页全失败**（一页都没成功）仍按老口径整批报错，不出现重试按钮（避免误导）。

### 1.4 两个"必须记住"的实现细节（都是本轮实测踩出来的）

1. **学校管线有失败页时必须 `throw`**：否则会拿一份**缺页的结构**去渲染预览，
   老师可能直接用它生成报告。`throw` 的内容里带上 `__schoolFailed` / `__schoolPages`，
   由 `handleSchoolError()` 统一处理（首次识别与重试**共用这一个函数**）。
   ⚠️ 第一版把 `schoolRun` 的 catch 写成"无条件清空失败页"，于是刚保存的失败页被自己擦掉，
   按钮点了没反应 —— 测试当场抓到。
2. **重试成功后要把"上次失败"从失败集合里去掉**：第一版把旧的失败页塞进 `failedSet`
   就不管了，于是**重试成功了它还在失败集合里** → 永远走"有页没成功"分支 → 结果出不来。

## 件 2：重复润色的确认（别再花第二次钱）

### 2.1 现象（用户提的）

老师已经润过一次，忘了 / 手快点第二次 → **又一次 AI 调用 = 又花一次钱**，
而且新文案会**覆盖**他可能已经手工调整过的那段。

### 2.2 做法

- 新增内存标记 `reportPolishMarks = { advice, attribution }`；
- 纯函数 `polishConfirm(marks, parts)` 决定"要不要问、问什么"，`confirmRepolish()` 弹确认；
- **三处入口同一套口径**：建议段按钮、错因列按钮、报告头合并按钮（合并按钮按"两部分"一起问一次）；
- 老师点**取消** → **一次 AI 都不调用**（有断言钉住）；
- 合并按钮内部的自动重试**不会**绕过取消（`canceled` 不重试）。

### 2.3 为什么用内存标记、而不是写进报告正文

工具把整篇报告当纯文本用（复制 / 打印 / 导出），任何写进正文的标记都会出现在
**老师给家长的那份**里；而且老师手改过之后标记也会失准。
标记在这几个时刻清空：**重新生成报告 / 导入新试卷 / 手动编辑报告 / 点「还原」**。

## 件 3：学情报告（`tool='analysis'`）也能删

### 3.1 用户原话

「我生成了好几份学情分析，现在不知道在哪里删除。」

### 3.2 现状（先查清"存在哪"）

- 学情报告**不是单独一张表**：它以一条 `feedback_history` 记录落库，
  `tool='analysis'`、`title='学情报告 · 10月16日 09:30'`、正文在 `text`；
- 详情页**本来就会列出**它（按归属分组），只是**删除按钮只开给了 `tool='manual'`**；
- 所以这件事**不需要动表结构**（红线守住了），只要把删除按钮的口径扩到 `analysis`。

### 3.3 做法

详情页那条判断从 `g.tool === "manual"` 改成 `g.tool === "manual" || g.tool === "analysis"`；
删除仍走**已有的** `DELETE /api/students?id=<historyId>`（只删这一条，**不碰**档案行、
也不碰别家工具的记录），确认框里明说"只删这一条，不影响这个学生的档案和其它记录"。

> ⚠️ 其它归属（辅导方案 / 试卷分析 / 课后反馈）**故意不开**这个按钮 ——
> 那些记录由各自的工具管理，档案页不该成为"到处都能删"的地方。

## 4. 测试与变异自证（用户规矩：真 bug 必须证明"退回去就会红"）

| 套件 | 变化 | 新增断言 |
|---|---|---|
| `vision-paper` | 31 → **41 项** | 两条管线的"只重试失败页"：失败页数与下标、按钮出现、重试后清零、**重试期间上游只被多调 1 次** |
| `paper-attribution-polish` | 35 → **42 项** | 已润过再点**先弹确认**、点取消**一次 AI 都没调**、三处入口口径一致、只润一段时提示不夸大、没润过不弹、重新生成会清标记 |
| `archive-students` | 21 → **28 项** | analysis 记录**有**删除按钮、其它归属**没有**、二次确认文案、点确定后那一条消失、**别的记录没被连带删**、**学生档案还在**（直连数据库核对） |

**变异自证 5 条（全部实做，都真的红了）**：

| # | 把什么退回去 | 结果 |
|---|---|---|
| M1 | 学校管线退回"一页失败=整批作废"（`catch` 里直接 `throw`） | `vision-paper` **37/41**，红的正是那三条 + 一条连带（按钮不出现） |
| M2 | 学校重试时**不跳过**已成功页 | **40/41**，`重试期间新增请求 3 次（期望 1）` |
| M3 | 图片管线重试时把**全部**页重发 | **39/41**，`0 次（期望 1）` 且失败页数变 3 |
| M4 | `polishConfirm` 假装"从来没润过" | `paper-attribution-polish` **37/42**，其中一条直接把危害打出来：**取消后上游仍被调 2 次** |
| M5 | 删除改成按 `name` 删（等于连学生一起删） | `archive-students` **27/28**：那条记录**没被删掉** |

> ⚠️ M5 的诚实说明：这个变异把"删除"变成**无操作**（学生名与 id 不匹配），
> 所以红的是"记录没消失"那条，而**不是**"档案还在"那条。
> "档案还在"这条是本功能最危险的失效方式（删一条记录却把档案带走），
> 但**没有直接的变异能演示它**（`manualScoreHooks().remove(id)` 就是按 id 删，
> 没有"改成按名字删还能删掉记录"的写法）。它靠的是**直连数据库**的独立核对。
