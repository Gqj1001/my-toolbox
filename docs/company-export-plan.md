# 公司模板导出 · 实现方案（第一期）

> 用户 2026-10 决策：**新增模块，不动现有生成逻辑**（math-plan / paper-analysis 的生成一行不改）。
> 分析底稿见 `docs/company-template-analysis.md`（固定内容 / 填空清单 / 来源表 / 差异对照）。

## 0. 一句话方案

把公司原件**在构建期切成三个独立模板**（保留 styles/theme/sectPr ⇒ 格式零走形），
运行期用 `company-docx.js` **按标签定位、只替换文字**、再把零件用现成的 `DocxBuilder.zip`
（STORE 打包，零依赖）重新打包 —— **不新建文档拼表格、不引第三方库、离线也能用**。

## 1. 先做哪个附件：**附件2 优先**（与用户建议一致）

| 顺序 | 附件 | 理由 |
|---|---|---|
| **① 先做** | **附件2**（表格式） | **数据最全、最实用**：题号/考点/错因全部来自试卷分析已经算好的东西，**不需要任何 AI 生成**，一次就能填满、可核验 |
| ② 同批 | **附件1**（文字式） | 与附件2 **同一套抬头数据**，引擎复用；六段长文一期**留空**（等老师写 / 二期接 AI 草稿） |
| ③ 下一批 | **附件3**（辅导计划） | 它的数据源在 **math-plan**（不是试卷分析），需要另一套数据组装与 UI；本期先把**模板与引擎**备好 |

## 3. 导出按钮放哪

**放在 paper-analysis 的「③ 生成报告」页**（报告面板下面新增一块「🏢 公司模板导出」），理由：
- 附件1/2 的数据**全部来自这一次试卷分析**（错题、考点、错因都在页面上现成）；
- 老师的心智顺序就是"生成报告 → 导出"，放同一页不用来回跳；
- **档案页不放**：那会逼着从这里跨工具拼数据（math-plan 的方案 + 试卷分析的考试），
  属于"同一件事两个来源"的老坑（本项目反复踩过），本期不做。

面板内容：附件1/2 单选 + 学校/考试类型（下拉）/入学成绩/入学排名/已学课时/单科总课时/本次成绩/本次排名 + 一个导出按钮。

## 5. 风险与取舍

| 风险 | 处理 |
|---|---|
| **样例文字漏进导出件**（最严重：把语文范文交给数学老师/公司） | 导出时**清空一切非标签格**；测试用语文样例关键词做**泄漏扫描**（附件3 尤其危险：合并导致"按标签清一行"只清掉每组第一行 —— 这个坑实际踩到并修掉了） |
| **格式走形** | 以原件为底只改文字；测试对比 tblBorders / tblPrEx / gridSpan / vMerge / tcBorders 与页面边距 |
| **公司改模板导致填错格** | 一律**按标签定位**，定位不到**抛错**（宁可导出失败也不填错）；行数变化（错题行）按表头现算列位 |
| **表格行里的 `w:tblPrEx` 被丢**（第一次实现踩到，表格线会消失） | `replaceCells` 只删 `w:tc`，行里其余 XML 全保留；有格式指纹断言守着 |
| 学校/排名/已学课时等**工具没有的数据** | 面板上**手填**（不新增数据库字段，评审期零风险）；排名留空也允许 |
| 附件3 的过程内容 | 一期留空（用户已定）；二期若做，**挂在那份辅导方案的 history 记录上**，不是学生身上（见 §7） |

## 6. 关于「上传试卷时顺手读失分题题干」的评估（**等你定，本期不做**）

**先说一个硬事实**：附件2 的「题目」列只有**"上传整张卷子"那条路**才可能拿到题干 ——
**学科网报告**（文字层 PDF / 截图）里**根本没有题干**，它只有题号/知识点/难度/细目表。
所以对"用学科网报告导入"的老师（目前的主力路径），这个想法**一点好处都没有**。

| 项 | 估算 |
|---|---|
| 改动点 | `vision-paper-structure` 的出参每题加一个 `stem` 字段（题干 30–60 字）+ 预览表格多一列可改 |
| 成本（学校卷子识别，按页调用） | 输出多 30–60 字/题 → 23 题一页约 **+700–1,400 输出 tokens**；按 flash 空闲价 4 元/百万 ≈ **+0.003–0.006 元/页**（多页线性叠加） |
| 风险 | ① 题干**抄错**会把错的东西写进交给公司的表里（比"用知识点顶替"更危险，因为看起来"像原文"）；② 输出变长，多页时更容易撞输出上限；③ 需要人工核对的工作量上升 |
| 收益 | 附件2 的「题目」列**名副其实**（不再与「考点」重复） |
| **建议** | **先不做**：① 主力路径（学科网报告）拿不到题干；② 抄错题干的代价高于"题目列与考点列重复"这个小瑕疵；③ 真要做，**等你说**"有多少老师是拍整张卷子导入的"，再决定是否值得 — 做的话我会同时加"题干必须人工核对"的界面提示 |

## 7. 第 5 题（过程列）的结论 —— **记在文档里，别丢**

用户想让「三次课后 / 阶段总结 / 效果评估（比对目标）及方案调整」通过**学生档案**来记。
方向对，但要分清**挂在哪条数据上**：

- 这几段内容是**跟着「这一份辅导方案」走的，不是跟着「学生」走的** ——
  第二期辅导时，上一期的"三次课后/阶段总结"**不能拿来用**。
- 所以：**一期先手填**（导出留空，老师在 Word 里写）；
- **二期若做**：入口放在**档案详情页的「辅导方案记录」旁边** ——
  点进**某一份方案**（那条 `tool='math-plan'` 的 history 记录）→ 记录过程 → **存到那条记录上**；
  **不是存在学生身上**。
- **本期不动学生档案的表结构**（不加字段、不改表）。
- 真要落库时，需要新增字段/新表 ⇒ **届时先停下来问用户**，不自己跑 SQL。
