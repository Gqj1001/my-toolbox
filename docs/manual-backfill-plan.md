# 档案页手动补录「历史数据」（老材料 AI 识别/解析入档）· 方案（待拍板）

> 用户 2026-10 的原始想法（逐字）：
> 「档案页这个我有些新想法，原先我们档案页不是可以手动录入成绩了嘛，我们现在也可以手动录入
> 之前这个程序没上线之前的反馈和试卷分析还有辅导方案呀！但是需要做 ai 的识别和解析，
> 这样我们就把之前的数据也能利用起来了，并且在分析上还能保证统一的格式，我们这里面不是有一个
> ai 学情分析的功能嘛，这样收集起来学生原来的数据后，得到的数据也更加的真实和贴合。」
>
> **本文只给方案，不动任何代码、不动任何表结构。** 请先看 §7 的四个待拍板项。

## 0. 一句话方案

**老材料（Word / PDF / 照片 / 粘贴文字）→ AI 只做"读懂 + 排版"，产出与现在工具**一模一样格式**的
正文 → 老师**预览逐项核对/修改** → 存成一条正常的档案记录（复用 `feedback_history`，不新增表）
⇒ 学情分析**不用改一行**就能把它算进去。**

关键认识：**这个功能的全部价值在于"让老数据长得像新数据"**，所以
**"统一的格式"不是我们新发明的格式，而是现有三个工具已经在写的正文格式**
（`【学情诊断】`、`【课时安排】共 N 课时`、`……核心薄弱板块集中在以下 N 处：…`、
`【主要失分点】`…）。只要 AI 输出往这些标记上靠，`src/lib/student-report.ts` 的抽取规则
**一段都不用改**，学情分析、AI 报告、成绩趋势全部自动接上。

## 1. 逐条回答你点名的 8 个问题

### ① 老材料是什么格式？分别怎么处理？

| 格式 | 能不能做 | 走哪条路 | 风险 |
|---|---|---|---|
| **粘贴文字**（从 Word/PDF 里复制的正文） | ✅ 最稳 | 直接进 AI 解析（最便宜、最准） | 无 |
| **Word（.docx）** | ✅ 能做 | 复用**已有**的 `/api/paper-analysis/parse-file`（服务端抽文字层）→ 再进 AI 解析 | 老 Word 里常有表格，抽出来会串行 → 预览里要能改 |
| **PDF（有文字层）** | ✅ 能做 | 同上（服务端抽文字） | 同上 |
| **PDF（扫描版，没有文字层）** | ✅ 能做 | 复用**已有**的浏览器端 pdf.js 逐页渲图 → 走视觉模型 | 按页计费；页数上限沿用 10 页 |
| **照片 / 截图（打印件拍照）** | ✅ 能做 | 复用**已有**的 `vision-paper` 那条"逐字抄录"管线 | **手写体识别不可靠** → 见下面 ⚠️ |
| **纯手写（老师的备课纸/手写反馈）** | ⚠️ **不承诺** | 走视觉模型试一把，识别不出的地方必须写 `[看不清]`，由老师补 | 手写错误率高，**不能自动入库**，一律要人核 |

> ⚠️ **口径建议（重要）**：手写件**不做"识别即入库"**。可以做，但走"预览 → 老师逐项改 → 确认"，
> 且识别不确定的地方**必须原样暴露**（现有视觉管线已经有 `[看不清]` + `uncertain` 这两个机制，直接复用）。

### ② 解析出来的内容存到哪？

**推荐 A：复用 `feedback_history`，用**已有的 `tool` 值**，不加新值、不加新表、不跑迁移。**

理由是本项目反复守的那条：**同一个东西只能有一个来源**。学情分析的抽取规则就是认
`tool` + 正文标记；给它单独造一张表 = 要在 `student-report.ts` 里再写一套聚合
（本项目在"第二个来源"上踩过好几次）。

| 选项 | 做法 | 好处 | 代价 |
|---|---|---|---|
| **A（推荐）** | 复用 `feedback_history`；老试卷分析存成 `tool='paper'`、老方案 `tool='math-plan'`、老反馈 `tool='feedback'`；用**正文里的一句来源说明**区分"补录"（例：`【补录说明】本条由旧材料识别补录，原始文件：2024年期中分析.docx`） | 学情分析/AI 报告/趋势**全部自动接上，服务端零改动**；与 `tool='manual'`（成绩）的关系清楚：那是"只有数字"，这是"有正文" | 归属看起来与真工具生成的一样（靠正文那句话区分） |
| B | 新加 `tool='legacy'`（要一条迁移） | 归属一眼可分 | 学情分析要**登记一种新来源**才认它；而且老卷子就**不再算作 paper**，paper 相关的抽取规则要全部复制一份 ⇒ 明确不推荐 |
| C | 单独一张表 | 与现有数据隔离 | ⚠️ **最差**：要重写整套聚合、AI 报告要读两处 ⇒ 直接违反"一个来源" |

> 📌 **与现有 `tool='manual'`（成绩）的关系**：
> `manual` 是"**只有分数**的一条记录"（没有正文）；本功能是"**带正文**的一条记录"。
> 两者**并存、互不干扰**：补录成绩仍然走那个小表单，补录历史材料走新面板。
> 一条老卷子材料如果只想知道分数，用补录成绩就够；想要错题/薄弱点进学情分析，才用本功能。

### ③ 存进去的"内容"长什么样（三种各自的统一格式）

**统一原则：照着现有工具生成的正文本抄格式**（这样抽取规则不用改）。

| 类型 | 存成的正文（**与现有工具同格式**） | 学情分析会用到什么 |
|---|---|---|
| **老试卷分析** | `【学员基本信息】`… `【试卷分析】`（得分/满分/得分率）`【错题分析】`表格（题号\|题型\|分值\|得分\|难度\|知识点\|失分原因）`……核心薄弱板块集中在以下 N 处：…` `【备考建议】` | **成绩趋势**（分数+满分）、**薄弱与失分**（那句"核心薄弱板块"原话） |
| **老辅导方案** | `【学情诊断】`… `【提分目标】50 → 90 分` `【课时安排】共 40 课时` `【阶段安排】`… | **课时累计**（共 N 课时）、**薄弱与失分**（学情诊断原话） |
| **老课后反馈** | `【课堂表现】` `【知识掌握】` `【主要失分点】` `【改进建议】`（`【】` 小标题正是现有反馈工具的格式） | **薄弱与失分**（主要失分点 / 知识掌握原话） |

> ⚠️ **AI 只做"读懂 + 排版"，不许自己发挥**：
> 提示词里要写死"**只允许写材料里出现过的内容**；材料没写的字段留空，不要推测；
> 看不清写 `[看不清]`"。这与现有视觉管线同一条红线（本项目已有先例与断言）。

### ④ AI 解析的输入从哪来？

一个入口，三种输入，**全部走已经有代码**：

```
档案详情页新增「📥 补录历史材料」面板
  ├─ 选择类型：试卷分析 / 辅导方案 / 课后反馈
  ├─ 选择输入：① 粘贴文字  ② 上传 .docx / 文字版 PDF  ③ 上传照片/截图（或扫描版 PDF）
  └─ 点「让 AI 整理成统一格式」→ 预览（可改）→ 确认入档
```

技术上是把这些**已有能力**串起来：`parse-file`（抽 Word/PDF 文字）、
浏览器端 pdf.js（扫描版 PDF 渲图）、`vision-paper`（图片逐字抄录）→ 再交给**新增的一个
"整理成统一格式"接口**（这条是本功能唯一的**新**服务端代码）。

### ⑤ 解析错了谁改？预览界面长什么样？

**老师改，且必须能改**。预览界面 = **一个大文本框 + 逐项核对提示**：

- 文本框里是 AI 整理好的**统一格式正文**（老师可直接编辑，像改 Word 一样）；
- 上面一行**核对清单**（把 AI 的关键判断列出来让人扫一眼）：
  `学生：张三 ✓` `日期：2024-04-15 ✓` `得分：88/150 ✓` `薄弱模块：导数、数列` `识别不确定处：2 处（见正文 [看不清]）`；
- **保存按钮**：`💾 存入档案`；旁边一句："存入后可在档案里看到，也会被学情分析算进去"；
- 保存后**不自动生成学情报告**（老师自己去点，与现在一致）。

### ⑥ 红线：AI 只能来自材料真实内容，不许编；识别错了要能改

| 红线 | 怎么保证 |
|---|---|
| 不许编内容 | 提示词写死"只许用材料里出现的内容"；不确定写 `[看不清]`；**预览里把 AI 的每个关键判断列出来**（人一眼能看出编没编） |
| 不许静默丢数据 | 材料里的字段没识别到 → 预览顶部**点名**"这几项没识别到：日期、得分"，而不是悄悄留空 |
| 识别错了能改 | 预览是**可编辑文本框**（最终以老师确认的文本入库），不是只读结果 |
| 不许自动入库 | **必须点确认**才写库；写库前不落任何东西（与"手填成绩"同一个节奏） |
| 与真工具数据可区分 | 正文首行写 `【补录说明】本条由旧材料识别补录，原始文件：<文件名>（<日期>）`；**这不影响任何抽取规则**（抽取只认它认得的那些标记） |

### ⑦ 和现有"学校卷子识别""手动补录成绩"什么关系？会不会重复？

| 现有功能 | 干什么 | 与本功能的关系 |
|---|---|---|
| **学校卷子识别** | 拍照**这一次考试的卷子** → 建**这一次**的 paper → 生成报告 | **不重复**：那条路的产物是"本次试卷分析"，走的是主流程（分值、逐题得分、报告）；本功能是"**把过去已有的分析文本搬进档案**"，不做分值分配、不生成报告 |
| **手动补录成绩** | 只有分数的一条记录 | **互补**：见 §2 的"关系" |
| **学情分析 / AI 报告** | 读档案里的记录生成报告 | **不改代码**（本功能的全部意义就是"让老数据长成它能读的样子"） |

> ⚠️ **边界要写死（否则会互相踩）**：
> 本功能**不生成报告、不做分值分配、不改 `paper` 结构**，只产出**一条正文记录**。
> 复用 `vision-paper` 的**抄录**能力，但**不碰** `paper-analysis` 的建卷流程。

### ⑧ 工作量、风险、取舍

| 项 | 估 |
|---|---|
| 工作量 | **1.5–2 天**（面板 + 预览 + 一个"整理成统一格式"的接口 + 三个类型的提示词 + 测试） |
| 成本 | 每次补录 1 次 AI 调用（**按材料长度**，几十页的老方案可能几毛钱；比视觉识别便宜，因为它只做排版不做识别） |
| 风险① | **AI 把老材料的内容"改写"了**（老师没细看就入库）→ 对策：预览必须人核 + 顶部点名不确定项 |
| 风险② | **老材料的正文与现有标记不匹配** → 抽取不到（学情分析里会**如实说"没抽到"**，不会编）→ 对策：预览里给出"这条会贡献哪些统计"的提示 |
| 风险③ | 手写件识别质量不可控 → 对策：**不承诺**，走预览人核 |
| 取舍 | **不做**"自动把老材料拆成结构化字段（逐题分值等）"—— 那是"重建一份 paper"，工作量与风险都翻倍，而且**对学情分析没有额外价值**（它只看分数、得分率、薄弱点原话） |

## 2. 数据流（一图看懂）

```
老师手上：老 Word / PDF / 照片 / 一段文字
        │
        ├─(文字/Word/文字版PDF)─→ 已有 parse-file（抽文字）
        └─(照片/扫描版PDF)─────→ 已有 vision-paper（逐字抄录，看不清写 [看不清]）
        │
        ▼
   新增接口：POST /api/students/backfill  ← ★ 本功能唯一的新服务端代码
      · 入参：{ kind:'paper'|'plan'|'feedback', text }
      · 用与现有工具**同格式**的提示词，让模型整理成统一正文
      · 出参：{ ok, text, facts:{date,score,full,weakPoints…}, uncertain:[…] }
        ⚠️ 服务端**不写库**（写库由老师点确认后，走已有的 /api/students 导入）
        │
        ▼
   预览（可编辑）→ 老师改 → 点「💾 存入档案」
        │
        ▼
   POST /api/students { op:'import', items:[{ tool:'paper'|'math-plan'|'feedback', … }] }
        │   （**现有接口，一行不改**）
        ▼
   feedback_history 多一条记录 ⇒ 学情分析 / AI 报告 / 成绩趋势**自动**把它算进去
```

## 5. 归属哪条会话线（要你定，也可能你自己就清楚）

- 这条链**服务端**在 `src/app/api/students/**`（网站线）；**前端复用** `public/tools/paper-analysis/*`
  里已有的"抽文字 / 逐字抄录"能力（工具线）。
- **推荐做法**：**不复制**工具里的代码，而是**直接调已有接口**（`parse-file` / `vision-paper`），
  新面板放在档案页（网站线）。这样两边都不用改工具本体 —— 但**新面板的 UI 归网站线**。
- ⚠️ 如果要在**工具页里**做这个入口（而不是档案页），那就动到 `public/tools/`（工具线），
  需要你明确授权。

## 6. 分三期（建议，降低一次性风险）

| 期 | 内容 | 为什么这样切 |
|---|---|---|
| **一期（建议先做）** | **粘贴文字 / Word / 文字版 PDF** 三种输入 + 预览可改 + 入库 | 最稳、最便宜、覆盖老师手上大部分"老 Word 反馈/方案"；**先把"统一格式 + 人核"这条路走通** |
| 二期 | 照片 / 扫描版 PDF（复用视觉抄录） | 风险高（手写、模糊），等一期验证了"格式与核对"流程再加 |
| 三期（可选） | 批量（一次补一个学生的多年材料） | 数量一多就需要"去重 + 冲突"设计，别在没验证前做 |

## 8. 本期**不做**（写清楚，免得以后误以为漏了）

- ❌ 不做"把老材料重建成一份 `paper`"（逐题分值/难度系数等）——
  学情分析**用不到**，工作量与风险却翻倍；
- ❌ 不做"自动识别学生姓名并归档到某个学生"——一律**在某个学生的详情页里**补录（避免 AI 认错人）；
- ❌ 不做批量导入与去重（三期再说）；
- ❌ 不动表结构、不加迁移、不改学情分析算法。
