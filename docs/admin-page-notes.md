# 管理后台（`/admin`）的开发者备忘

> 这份文档的存在原因：2026-10 用户看后台时指出「页面上有很多注释性的文字，能隐藏掉吗」。
> 那些文字讲的是**实现细节**（文件路径、`SECURITY DEFINER`、`requireAdmin`），对每天点按钮的管理员
> 没有用，但对下个会话**是有价值的** —— 所以从页面上**挪到这里**，而不是直接删掉。
>
> ⚠️ **约定：后台页面上只放"管理员需要知道的"**（点了会发生什么、多久生效、能不能撤销）。
> 实现细节一律写进本文件或对应专题文档，**不要再往页面上加**。

## 1. 「功能开关」区块（2026-10 第十三批）

页面上现在只留一句：**关掉后对应入口消失，代码与数据都不变，最多 30 秒全站生效（不用重新部署）。**

被挪走的技术细节：

- **开关清单登记在** `src/lib/feature-flags.ts` 的 `FEATURE_FLAG_REGISTRY`
  —— **代码是"谁受影响"的唯一来源**，数据库那张 `feature_flags` 表**只存状态**。
- 新增一个开关要**同时改三处**（缺一条后台就管不住）：
  ① 登记表加一条（key / 标签 / 说明 / **关闭参数名** / 作用于哪个工具）；
  ② 迁移 `0018_feature_flags.sql` 里补一条同 key 的种子；
  ③ **工具页认这个参数**（例：`companyExportDisabled()` 读 `?nocompanyexport=1`）。
- 参数**怎么送到工具页**：`ToolPageShell`（服务端）读开关 → 关掉时把参数拼到
  **iframe 的 src** 上 ⇒ 工具页代码一行都不用改。
- **读不到表时一律当"开启"**（数据库抖一下不该悄悄把功能干掉），后台会点名要跑哪个迁移。
- 优先级：**URL 参数（含后台拼的）> 代码常量** ⇒ 后台关掉＝一定关。
- 生效速度：进程内缓存 30 秒（与 `tools` 表同一套做法）；后台改完会主动
  `invalidateFeatureFlags()`，**本实例立刻生效**，其它实例最多滞后一个 TTL。

## 2. 权限与安全边界（原本写在页面底部，现已挪到这里）

- **权限判定以 `user_roles` 表为准**（不是前端、也不是环境变量）；
- **用户列表**通过 `SECURITY DEFINER` 函数 `admin_list_users()` 读取，
  函数内部会**再次校验**管理员身份（双保险）；
- **所有会员操作都在 Server Action 中执行**，并在**服务端**用 `requireAdmin()` 校验调用者身份；
- ⚠️ **前端隐藏按钮不构成安全边界** —— 页面上藏起按钮只是体验，真正的保护在服务端。
  这一条在本项目是硬口径（见 `docs/project-overview.md` 第三节之二）。
