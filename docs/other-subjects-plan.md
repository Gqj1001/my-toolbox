# 全科适配：都要做哪些工作

> 结论先说：**最难的不是解析试卷，而是「每个学科的知识模块分类 + 归因话术」。**
> 试卷解析器本身基本是学科无关的，但归因引擎、模块分类、知识点词典、AI 提示词
> 目前**全部是按高中数学写死的**。

---

## 一、先说好消息：哪里不用改

工具的关键设计正好对多学科友好：

| 部分 | 为什么基本不用改 |
|---|---|
| `paper-parser.js` 的**细目表解析** | 按「题号｜难度系数｜知识点」这种**结构**解析，不认学科。知识点只是一串文本，原样带走 |
| `normType()` | 别名表认不出「现代文阅读」这类新题型时，**原样保留**该字符串，不会丢题 |
| 报告 Word 模板 | 占位符填充，表结构（错题分析、题型分布）各科通用 |
| `seedRecords()` / 分值逐题编辑 | 纯算术，与学科无关（第二批刚做完） |
| `_scoreAssign()` 的余额吸收 | 「客观题定额 + 大题吸收余额 + 逐题可编辑」这套逻辑各科都成立 |

**所以各学科报告能解析出来、能填分、能导出 Word —— 这部分工作量比想象小。**

---

## 二、必须改的地方（按工作量从大到小）

### A 类 · 题型与分值结构 —— 各科差异最大的一项 ⚠️

**文件**：`public/tools/paper-analysis/js/paper-parser.js`

现状（数学专用）：

```js
const TYPE_ALIAS = { '单选题':…, '多选题':…, '填空题':…, '解答题':…, '判断题':… };
const order      = ['单选题','多选题','填空题','判断题','解答题'];   // 写死顺序
const DEFAULT_PER = { '单选题':5, '多选题':6, '填空题':5, '判断题':4, '解答题':12 };
const TYPE_PRESETS = [ 新高考 I/II 卷, 北京卷, 全国甲/乙卷, 天津卷, 上海卷 ];  // 全是数学卷
const DEFAULT_PER 的「解答题吸收余额」也假设了「客观题 + 一个大题块」
```

**各科的真实差异**（这就是为什么需要老师的文件）：

| 学科 | 题型差异 |
|---|---|
| 语文 | 现代文阅读 / 古诗文阅读 / 语言文字运用 / 写作（作文 60 分独立成块）——**没有"填空题"概念** |
| 英语 | 听力 / 阅读理解 / 七选五 / 完形填空 / 语法填空 / 短文改错 / 书面表达，**分值碎、题型多** |
| 物理 | 单选 / 多选 / 实验题 / 计算题，**实验题是独立大块** |
| 化学 | 单选 / 多选 / 非选择题（含实验探究） |
| 生物 | 单选 / 多选 / 非选择题 |
| 政治/历史/地理 | 单选 / 材料分析题（主观题块头很大） |

**要做**：① 每科的 `TYPE_ALIAS` 补充 ② 每科的题型顺序 ③ 每科每题的常见分值
④ 每科的卷面结构预设（相当于把「新高考 I/II 卷」那 6 条换成各科的）
⑤ 「吸收余额」的那个"大题块"要能按科指定（语文是作文、英语是书面表达）

### B 类 · 知识模块分类 + 归因话术 —— 真正的大工程 ⚠️⚠️

**文件**：`public/tools/paper-analysis/js/knowledge-classifier.js`（132 行，纯数学）

现状：12 个高中数学模块（三角函数／解析几何／立体几何／导数／数列／向量／概率统计／不等式／计数原理／集合／复数／函数），
每个模块一条正则 + **一句教学建议**（`ADVICE`），例如：

```js
'立体几何与空间向量': '固化"建系→写坐标→求法向量→算角"的步骤，证明题先背全定理条件',
```

**要做**（每科各来一套）：
- 该学科的**知识模块划分**（各科不同：历史按时间/专题、地理按自然/人文、英语按语言技能…）
- 每模块的**关键词正则**（这是最费工的，数学那 12 条正则里塞了几百个关键词）
- 每模块的**教学建议话术**（12 条 × 8 科 = 96 条要写）
- 语文/英语/历史这类"文科"的模块划分**没有标准答案**，需要跟老师确认口径

### C 类 · 知识点权威词典

**文件**：`public/tools/paper-analysis/js/kp-dict.js`（198 行 / 约 300 条，全数学）

现状：把学科网返回的原始知识点名映射到模块 id（`'共轭复数的概念及计算' → 'cplx'`），
注释说「已验证可复现学科网官方归并」。

**要做**：每科重做一份等价词典。**难点是口径**：
其他学科在学科网里的知识点粒度是否和数学一样细？这个**只能拿到真实报告才知道** ——
所以收集文件是第一步，不能跳过。

### D 类 · AI 建议段的提示词（最容易漏）

**文件**：`src/app/api/paper-analysis/ai-advice/route.ts`

现状写死了：

```js
"你是一位有十几年经验的高中数学教师，正在给学生家长写《试卷分析表》里的「教学辅导建议与安排」…"
```

**要做**：按学科（+ 初高中）切换这个系统提示词。**这一条必须改**，
否则英语卷子会由"高中数学教师"来写建议，一眼就穿。

### D2 类 · 归因引擎（比预想的好，但仍有数学内容）

**文件**：`public/tools/paper-analysis/js/error-engine.js`

查过之后要给个**更正面的结论**：它的核心是 **11 类失分类型的特征正则**
（计算失误 / 逻辑与分类讨论 / 概念不清 / 知识漏洞 / 方法不当 / 策略失误 / 心态与畏惧 等），
这类划分**是学科无关的**，各科都能用 —— 这部分不用重写。

但里面仍有两处数学内容，各科要替换：

1. `BANDS` 里各分数段的**提分优先顺序**，写的是数学模块名：
   ```js
   order:['集合','复数','平面向量','三角函数与解三角形','计数原理与二项式'],   // 低分段
   order:['导数及其应用','平面解析几何','立体几何与空间向量','概率与统计'],   // 高分段
   ```
   → 每科要有自己的「先补哪块、再补哪块」顺序（这是教学判断，得问老师）
2. `TYPES` 里部分 `advice` 话术含数学动作（如「求导、通分、联立、数列求和」）
3. 源码里已留了伏笔：`diagnoseAll(q, records, subject)` 的注释写着 **`@param subject 科目（暂只做数学）`**
   —— 说明原作者已经预留了多学科入口，**接口不用改，只要让 subject 真正生效**

### E 类 · 初高中差异（不只是学科）

`senior/` 与 `junior/` 分开是对的，但要注意**同一学科初高中也是两套**：
初中的知识模块、题型分值、难度系数口径都与高中不同（比如初中物理的"简单机械"、初中化学的"酸碱盐"）。
所以适配矩阵是 **2（学段）× 8（学科）= 16 套**，不是 8 套。

### F 类 · 界面与编排

- **学科选择器**：现在没有。要么在工具页加一个「学科/学段」选择（推荐），要么按 8 个独立工具挂 8 个路由
- **`public/tools/math-plan.html`（辅导方案）也确认是数学专用的**，证据两处：
  - `<title>锐满分 · 高中数学辅导方案生成器</title>`
  - 生成的 Word 表头里学科是**写死的**：`<th>学科</th><td>数学</td>`

  你说"辅导方案也会更新"是对的 —— 这个工具是**独立的一份**，与试卷分析不共享代码，
  所以它的适配是有独立工作量的一份活（好在其结构「卷面结构 / 学情诊断 / 教学方法 / 复习阶段」
  各科通用，主要换的是上面的模块与话术）
- `examSubject` 之类字段目前从学生档案取，要确认能驱动上面的选择

## 三、三种实现路线（建议选第 2 种）

| 路线 | 做法 | 评价 |
|---|---|---|
| 1 · 各科独立一套 | 每科复制一份 `js/` 与 `index.html` | ❌ 8 科 = 8 份重复代码，以后修 bug 要改 8 遍 |
| **2 · 科目包（subject pack）** | 抽出 `{ TYPE_ALIAS, order, DEFAULT_PER, TYPE_PRESETS, MODULES, ADVICE, KP_DICT, AI_PROMPT }` 这一组配置，每科一个 `subjects/<subject>.js`；引擎不变，只换配置 | ✅ 推荐。引擎的通用部分已经验证过（第二批 109 项测试保着），改配置风险最低 |
| 3 · 最小可用 | 只改 D 类提示词 + A 类题型别名 | ⚠️ 能出报告，但模块归因会退化成"其他"，报告质量明显下降 |

**路线 2 的改造量**：抽出配置层 + 把 `knowledge-classifier.js`、`kp-dict.js`、`paper-parser.js`
里写死的部分改成读配置（外加 `error-engine.js` 的 `BANDS.order` 与部分话术）。
数学那套原样搬进 `subjects/math-senior.js` 即可，
**并且现有 109 项测试正好成为"数学不能被改坏"的回归网**。

## 四、建议的执行顺序

1. **收素材**（现在这一步）—— 按 `other-subjects/README.md` 的两类文件收集
2. **单科试点** —— 挑**物理**（与数学最接近，题型/分值/知识点结构差异最小），
   用它验证「科目包」这个架构是否成立
3. **抽配置层** —— 试点通过后再动引擎，把数学也变成"一个科目包"
4. **横向复制** —— 物理跑通后，化学/生物（理科）应该很快；
   语文/英语/政史地（文科）因为模块划分没有标准口径，需要跟老师一轮确认
5. **辅导方案同步** —— `math-plan.html` 同样按科目包思路改

## 五、为什么一定要老师的真实文件

不是"看一下就能写"，而是三件事**只有真实文件能回答**：

1. **各科在学科网里的知识点粒度** —— 决定 C 类词典怎么写（数学那份是"已验证可复现官方归并"，
   其他学科是否同样可分，未知）
2. **各科的题型命名习惯** —— 「七选五」「材料分析题」这些词在不同学校/地区叫法可能不同，
   只能从真实报告里收词
3. **老师的话术** —— B 类里的 `ADVICE` 是给家长看的，必须像该科老师说的话（数学那句"建系→写坐标→求法向量"换成历史，要写什么？）
