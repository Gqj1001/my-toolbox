## 1. 现状：数学版现在是怎么跑的

### 1.1 两个入口，一条下游

```
入口 A（质量最高）：学科网「试卷分析报告」
   上传 docx/txt/截图 → 解析出「题型表 + 细目表（题号|难度系数|知识点）+ 知识点分析」
   ↓
入口 B（没有学科网报告时）：学校自己的卷子
   传照片/扫描PDF → 视觉模型逐页抄录文字 → 再识别成结构化题目
                → 或直接「结构识别」一次拿到 {题型块, 逐题, 分值, 得分}
   ↓
【同一条下游】
   分值分配（按题型惯例 + 逐题可改 + 余额吸收）
   → 逐题录分（可手动、可 AI 读批改痕迹）
   → 归因（11 类失分类型，正则特征）
   → 知识模块归类（12 个高中数学模块）
   → 导出：公司附件1 / 附件2（+ 本工具自己的报告 Word）
```

### 1.2 关键模块（都在 `public/tools/paper-analysis/js/`）

| 文件 | 行数 | 作用 | 学科相关度 |
|---|---|---|---|
| `paper-parser.js` | 597 | 解析学科网报告 + 分值分配 | **中**：题型别名表、题型顺序、6 种卷面预设、每题默认分值全是数学 |
| `vision-paper-structure`（服务端） | 255 | 看图 → `{blocks, questions[{no,type,knowledge,score,got}]}` | **高**：题型枚举写死 5 种、提示词写"资深高中数学老师" |
| `error-engine.js` | 395 | 11 类失分类型 + 分档提分顺序 | **低**：11 类本身学科无关；但 `BANDS.order` 里是数学模块名 |
| `knowledge-classifier.js` | 114 | 知识点文本 → 12 个数学模块 | **高**：全部数学 |
| `kp-dict.js` | 192 | 学科网知识点名 → 模块 id（约 300 条） | **高**：全部数学 |
| `narrator.js` | 294 | 生成叙述文字 | 中 |
| `app.js` | 2905 | 界面与流程（多页识别、合并、填分、导出） | 低（流程学科无关） |

### 1.3 你构想里的 4 个环节，现状对照

| 你的构想 | 现在有没有 | 缺什么 |
|---|---|---|
| ① 上传整张卷子（照片/PDF） | ✅ **有**：支持多页（1–20 页自动分批）、单页失败可单独重试 | 只差**移动端好用的拍照入口**（见 §5） |
| ② AI 识别题号/题型/大概分值 | ✅ **有**：`vision-paper-structure` 已返回 `blocks + questions + score`，且**卷面没印分值就填 null（不猜）** | 只差**题型词表换成各学科的** |
| ③ 考点：手动 or AI 初稿 | ✅ **半有**：识别时已给 `knowledge`（每题 1–3 个，教材措辞，看不出就留空） | 缺**"AI 补空白/单题重写"按钮**与**考点白名单**；缺**考点→模块**的按学科词典 |
| ④ 录成绩 + 导出附件1/2 | ✅ **有**：逐题录分、AI 读批改痕迹、附件1/2 都能导 | 缺**附件1 的三段归因自动生成**（现在留空）；缺**各学科的归因话术** |

**所以这不是"新做一个工具"，是"把一个已经跑通的数学工具，拆成'引擎 + 每个学科一份配置'"。**
这与我们做「辅导方案生成器」时的情形**不同**：那里是口径不同（一行一次课 vs 一行一模块），所以要新建；
这里**流程与口径完全一样**，只是配置不同。

## 2. 泛化到全学科：难点在哪（按"难 × 费工"排序）

### 2.1 ⚠️⚠️ 最硬的一条：**题型体系根本不一样**

现在代码里题型是**5 个固定枚举**：单选 / 多选 / 填空 / 判断 / 解答，并且有固定顺序、固定默认分值。
换到别的学科，这套**直接不成立**：

| 学科 | 真实题型（老师口中的叫法） | 为什么塞不进现有 5 类 |
|---|---|---|
| **语文** | 现代文阅读（信息类/文学类）、文言文阅读、古代诗歌阅读、名篇名句默写、语言文字运用、**写作** | 没有"填空题"概念；"写作"是 60 分独立块 |
| **英语** | 听力（第1节/第2节）、阅读理解、**七选五**、完形填空、语法填空、短文改错、**书面表达**（应用文/读后续写） | 分值碎、题型多；七选五/语法填空都不是"填空" |
| **物理** | 单选、多选、**实验题**、计算题 | 实验题是独立大块，不是"解答题" |
| **化学** | 单选、不定项选择、非选择题（含实验探究） | "不定项"≠"多选"（评分规则不同） |
| **生物** | 单选、多选、非选择题 | — |
| **政治/历史/地理** | 单选、材料分析题（主观题块头很大） | 主观题常是"一段材料带 3–4 小问" |

**结论**：题型**不能是代码里的枚举**，必须是"科目包给一份有序词表"，代码只做"查表 → 认不出就原样保留（不丢题）"。

### 2.2 ⚠️ "题号"不是数字

现有 `no` 是数字。但真实卷面里：

- 语文/英语有 **14(3)**、**18(2)** 这种小问编号；
- 英语听力分 **第1节 / 第2节**，编号规则不同；
- 语文/英语的 **写作** 往往没有题号（就写"写作"或"作文"）；
- 化学/生物的非选择题常是 **"16.(1)(2)(3)"**。

**结论**：`no` 必须是**字符串**，且允许"无题号"的块（用 `label` 代替）。

### 2.3 ⚠️ "一个材料带多道题"（语文/英语最典型）

语文一篇现代文带 4 道题、英语一篇阅读带 4 道题。
如果按"每题独立"存，会出现两个问题：
- 考点要重复填 4 次（同一个材料）；
- 归因统计时"这篇材料"算几次说不清。

**结论**：需要**共享材料组（stem）**：一组题指向同一个材料，考点可挂在"材料"上，具体题再补自己的点。

### 2.4 ⚠️⚠️ 最费工的一条：**知识模块划分 + 归因话术**

现在的 12 个模块 + 12 条教学建议 + 约 300 条知识点词典，全是数学。
每加一个学科，要重做一套：

| 要做的 | 数学现状 | 其他学科为什么难 |
|---|---|---|
| 知识模块划分 | 12 个（三角/解析几何/立体几何/导数/数列/向量/概率统计/不等式/计数原理/集合/复数/函数） | 语文/英语/历史**没有标准答案**（按题型？按文体？按能力？）只能跟老师定口径 |
| 每模块关键词正则 | 12 条里塞了几百个词 | 语文的"散文"和"文学类文本"边界模糊 |
| 每模块的教学建议话术 | 12 条 | 要像该科老师说的话（数学写"建系→写坐标"，历史该写什么？） |
| 分档提分顺序 | `BANDS.order` 写的是数学模块名 | 每科要有自己的"先补哪块" |

### 2.5 ⚠️ 知识点词典：**口径未知**

`kp-dict.js` 现在做的是"把学科网返回的知识点名 → 归到 12 个模块"，注释说"已验证可复现学科网官方归并"。
**其他学科在学科网里的知识点粒度是否同样细？** —— 这个**只能拿到真实报告才知道**。
如果某个学科的知识点很粗（比如历史就写"近代史"），那模块归因会大面积落到"其他"。

### 2.6 还有三个"学科特有"的坑（容易被忽略）

| 坑 | 说明 | 处理建议 |
|---|---|---|
| **作文 / 主观题** | 不能判"对/错"，只能整体给分；作文还有分项（内容/结构/语言） | 错题明细允许"分项得分"；错因用"要点不全/结构松散"这类话术，不用"算错" |
| **英语听力** | 音频不在卷子上，卷面只有题目 | 听力题照样能列（有题号和选项），但**无法从卷面判断难度**，要允许整体标注 |
| **初高中 × 学科 = 矩阵** | 初中物理的"简单机械"、初中化学的"酸碱盐"都是独立体系 | 科目包按 **2 学段 × N 学科** 分开，不是 N 个 |

### 2.7 难度总表

| 难度 | 项目 | 预计工作量 |
|---|---|---|
| ★★★ | 每科"模块划分 + 归因话术 + 知识点词典"（内容活，需老师确认） | 每科 1.5–3 天（含老师一轮确认） |
| ★★ | 题型词表 / 分值惯例 / 卷面预设（配置化） | 每科 0.5 天 |
| ★★ | 数据结构升级（题号字符串 / 共享材料 / 考点带来源） | 2 天（一次做完，所有学科受益） |
| ★★ | 抽"科目包"层（改 4 个引擎文件 + 3 处提示词） | 3–4 天 + 回归 |
| ★ | 界面：学科选择、考点批量编辑、三档导出 | 2 天 |
| ★ | 附件1 三段归因接学情分析 | 1.5 天 |
| ★ | 手机端拍照入口 | 2 天 |

> 估算口径：**含写测试与回归**。一期（数学+物理可用）= 约 **10–12 天**。

## 3. 架构建议：改造现有工具，加"科目包"层

### 3.1 三条路线对比

| 路线 | 做法 | 评价 |
|---|---|---|
| A. 各科复制一套 | 每科复制 `js/` + `index.html` | ❌ 8 科 × 2 学段 = 十几份 2900 行界面，修一个 bug 改十几遍 |
| **B. 科目包（推荐）** | 抽出 `{ 题型表, 分值惯例, 卷面预设, 模块分类, 归因话术, 知识点词典, AI 提示词 }` 成 `subjects/<学科>-<学段>.js`；**引擎与界面不变** | ✅ 与「辅导方案生成器」同一套架构（已验证可行），加学科 = 加一个配置文件 |
| C. 最小可用 | 只换 AI 提示词里的"高中数学老师" | ⚠️ 能出报告，但模块归因会大面积退化成"其他"，报告质量明显下降 |

### 3.2 为什么**不**新建第二个工具

「辅导方案生成器」当时新建，是因为**口径不同**（一行一次课 vs 一行一模块）。
试卷分析这里是**流程和口径完全一样**，只是配置不同。新建的代价：

- 要复制 2900 行 `app.js`（多页识别、合并、填分、导出、档案联动都在里面）；
- 以后修一个 bug 要改两处，两份会慢慢走叉（本项目最踩过的坑就是"第二个来源"）；
- 现有 **333 项测试**本来是"数学版不能被改坏"的现成回归网，新建就浪费了。

**但改造有一个真实代价**：数学老师每天在用的界面会多一个"学科/学段"选择器。
缓解办法：**默认选中数学 + 记住上次选择**，数学老师的操作步骤**一步都不多**。

> ⚠️ 这条要你拍板（见 §7 问题①）：能接受"数学版界面多一个下拉"吗？不能接受就走新建路线。

### 3.3 科目包里装什么（一个文件的样子）

```js
// subjects/physics-senior.js  —— 纯配置，不含逻辑
{
  key: 'physics', stage: 'senior', name: '物理', fullScore: 100,
  // ① 题型词表（有序）+ 别名 + 默认分值
  types: [
    { id: 'single',  label: '单选题', aliases: ['选择题','单选'], per: 4 },
    { id: 'multi',   label: '多选题', aliases: ['多选','不定项'], per: 5 },
    { id: 'exp',     label: '实验题', aliases: ['实验探究题'],   per: 10 },
    { id: 'calc',    label: '计算题', aliases: ['解答题','大题'], per: 12, absorb: true } // ← 吸收余额的块
  ],
  // ② 卷面预设（相当于现在的"新高考I/II卷"）
  presets: [{ name: '河北新高考卷', total: 100, dist: { single:[7,4], multi:[3,5], exp:[2,10], calc:[3,14] } }],
  // ③ 知识模块 + 关键词 + 教学建议（就是现在 knowledge-classifier 的 12 条，换成本科）
  modules: [
    { id: 'mech', name: '力学', match: /牛顿|动量|机械能|圆周|平抛/, advice: '先把受力分析画完整，再列方程' },
    …
  ],
  // ④ 分档提分顺序（就是现在 error-engine 里 BANDS.order）
  bands: { 1: ['mech','elec'], 2: […], 3: […] },
  // ⑤ 知识点词典：学科网知识点名 → 模块 id
  kpDict: { '牛顿第二定律': 'mech', … },
  // ⑥ AI 提示词片段（各科老师话术）
  prompts: { persona: '你是一位有十几年经验的高中物理教师', knowledgeHint: '用「牛顿第二定律」这类教材措辞' }
}
```

**加一个学科 = 加一个这样的文件 + 在 manifest 里加一行**（与「辅导方案生成器」完全同一套做法，已验证）。

## 4. 数据结构设计（重点）

### 4.1 现在的问题（数学版的形状）

```js
questions: [{ no: 1, type: '单选题', knowledge: ['集合的交集运算'], score: 5, got: 3, uncertain: false }]
blocks:    [{ type: '单选题', count: 8, perScore: 5 }]
records:   { '1': { full: 5, got: 3, note: '…' } }      // 题号当对象键
```

这套形状在数学里够用，但**容不下 §2.2–2.3 的情况**（字符串题号、无题号块、一材料多题、作文分项）。

### 4.2 建议的三层模型

```
第 1 层：Paper（一份卷子）
   ├─ 元信息：学科/学段/年级/考试名/日期/满分/来源（学科网 or 拍照 or 手动）
   ├─ blocks[]：题型分块（有序，label 来自科目包词表；认不出的归 __unknown__，不丢题）
   └─ stems[]：共享材料组（语文"一篇现代文"、英语"一篇阅读"；可空）

第 2 层：Question（一道题）
   ├─ no：**字符串**（'1' / '14(3)' / '作文' / '听力1'）
   ├─ blockId：属于哪个题型块
   ├─ stemRef?：指向共用材料
   ├─ score：卷面分值（可空）
   ├─ scoreParts?：分项（作文：内容/结构/语言）
   └─ knowledge[]：考点（**带来源与置信度**，见 §4.3）

第 3 层：Attempt（这次作答）
   ├─ 每个 qid 的 got（可空）、uncertain、用时
   ├─ 判分方式：auto（识别）/ manual / parts（分项）
   └─ 归因结果：每个错题的失分类型 + 错因文本
```

**为什么这样能容下各种题型**：
- 题型**不在代码里**：词表来自科目包，代码只查表；认不出就放进 `__unknown__` 并保留原文（沿用现在 `normType` 的"原样保留不丢题"策略）。
- 题号是字符串 ⇒ 小问、无编号块、听力分节都能装。
- `scoreParts` 让作文/主观题不被"对错"逼死。
- `stems` 让"一文多题"的考点只填一次。

### 4.3 考点（知识点）要**带来源**——这是最关键的一个设计

```js
knowledge: [
  { name: '牛顿第二定律', source: 'imported', confidence: 'high' },  // 学科网细目表带来的
  { name: '受力分析',     source: 'ai',       confidence: 'mid'  },  // 视觉模型给的初稿
  { name: '摩擦力方向',   source: 'manual',   confidence: 'high' }   // 老师确认/补的
]
```

**为什么必须带来源**：
1. 界面上要能区分（AI 给的标灰、可一键清空；老师填的不动）；
2. 导出时可以选"只用老师确认的"（宁缺毋滥）；
3. 以后排查"AI 总把这类题认成什么"有据可查。

## 5. 考点（知识点）的 AI 辅助：怎么落地

### 5.1 三档来源，优先级固定

| 优先级 | 来源 | 质量 | 说明 |
|---|---|---|---|
| 1 | `imported`（学科网细目表） | ★★★ | 官方归并过的知识点，最准。有报告就走这条 |
| 2 | `manual`（老师填/改） | ★★★ | 一经老师确认就锁定，AI 不再覆盖 |
| 3 | `ai`（视觉模型初稿） | ★★ | 每题 1–3 个，教材措辞，**看不出就留空** |

### 5.2 AI 生成的四条护栏（沿用本项目已在用的那套）

1. **只给 1–3 个**，宁少不多（多了只是噪音，家长也不看）。
2. **必须用科目包给的"高频考点词表"措辞** —— 不是自由发挥，允许的写法在配置里。
3. **拿不准就留空**，绝不编（现有提示词已经写死"看不出考什么就少写或留空数组，不要编"）。
4. **一律标 `source:'ai'`**，导出时老师可勾"不用 AI 猜的考点"。

### 5.3 老师侧的交互（三种粒度，缺一不可）

| 场景 | 交互 | 说明 |
|---|---|---|
| 整卷初稿 | 识别完自动带出考点（现状已有） | 不额外点按钮，避免"多点一次"（你上次提过这条） |
| 批量补空白 | 一个按钮「AI 补空考点」（只填空着的，不覆盖已填） | **会员功能**（要花钱调模型） |
| 单题重写 | 每题一个「重写」，像「辅导方案」那样 | 不满意就重来 |

> 还有一条**不做**：不自动把 AI 考点写进"已确认"状态 —— 必须老师看一眼（这是本项目所有 AI 功能的统一红线）。

### 5.4 考点 → 知识模块：**词典优先，AI 兜底**

归因统计用的是"模块"，不是"考点原文"。转换顺序：

```
考点原文 → ① 科目包 kpDict 查表（确定性，最准）
         → ② 模块正则匹配（科目包 match）
         → ③ 都认不出 ⇒ 归入「其他」，并在界面提示"这 N 条没归类，请手动选模块"
         （可选）④ 会员：把"其他"里的批量交给 AI 归类，逐条可改
```

**必须让老师能手动改模块**（下拉），否则词典没覆盖到的学科会大面积"其他"。

> ⚠️ 一个容易做错的地方：**别把"考点"和"模块"合成一个字段**。
> 考点是给家长看的（"牛顿第二定律"），模块是给自己统计的（"力学"）。
> 合成一个，要么家长看不懂，要么统计不准。

### 6.3 我的建议：**不合并成一份，改成"一次录入、三档导出"**

**答复你的问题**：不建议把两份塞进同一个 Word；但也**不建议"择一使用"**。

**为什么不合并（三条硬理由）**：

1. **两份模板各自带抬头和签字栏**。物理合并 = 一个文件里出现两份抬头、两处签字 → 看起来像"两份拼起来的"，反而不专业。
2. **公司是按"附件1 / 附件2"编号归档的**。合并成一个文件，机构收上去没法按编号归类。
3. 技术上要拼接两套 OOXML（重映射 `rId`、样式、页面设置），**约 1 天且风险中等**，换来的好处只是"少点一次下载"。

**为什么不建议择一**：

- 只留附件2 ⇒ 丢掉"为什么考成这样"的归因（家长最想看的就是这个）；
- 只留附件1 ⇒ 丢掉逐题明细（教研跟错题要靠它）。
- 两份的**独有块互不重叠**（一个宏观归因、一个逐题明细），删哪份都缺一半。

**建议做成这样（同一份数据，三种产出）**：

```
界面上：一次录入
   ├─ 抬头（共用，只填一次）
   ├─ 三段措施（**共用，只写一次**，两份都用它）
   ├─ 三段归因（附件1 用；先由 AI 用「本次+历史」生成初稿，老师改）
   └─ 错题表（附件2 用；AI 归因 + 老师改）

导出按钮三个：
   [ 导出附件1 ]  [ 导出附件2 ]  [ 两份一起（两次下载） ]
```

> "重合度高"的真正价值不是"合成一个文件"，而是**"只录一次"**。这一点现在就能做到：
> 一份 `data` 同时喂给 `CompanyDocx.build('附件1', data)` 和 `build('附件2', data)`，
> 措施段落用同一个字段。**技术上零风险，今天就能做。**

### 6.4 附件1 的三段归因从哪来（这是本次最值钱的一块）

档案里的历史（学情分析：历次成绩、历次薄弱点、历次反馈）

这样附件1 就从"老师硬写"变成"有数据支撑的初稿"，也就**真正用上了你攒的档案**。

## 7. 手机拍照这件事：我建议换一种解法

你的原话里有个真实的别扭："怎么解决用手机拍照、用电脑做文件的问题，总觉得差一些，麻烦。"

**先说我为什么觉得"微信传电脑"是最差的一条路**：
- 微信会**压图**（长卷子压缩后小字会糊，识别率直接掉）；
- 跨设备找文件、重命名、区分"这是谁的卷子"全靠人；
- 一期就把"最脏的活"留给老师，体验上永远差点意思。

**我的建议（一期就能做，比微信省 3 步）**：

> **不做"文件传输"，做"同一账号多端"。**
> 手机浏览器打开 `010034.xyz/tools/paper-analysis` → 登录（已有）→ 拍照上传 →
> 识别结果**直接落进云端草稿** → 电脑上打开同一学生，接着填考点/成绩/导出。

- 图**不过微信**，原图直传，识别率最高；
- 不用找文件、不用改名（草稿里已经带学生+日期）；
- 移动端只需：上传按钮支持 `capture`（直接调相机）、单列布局、多页顺序可拖动。

**二期再上"扫码传图"**（体验更好）：
电脑端点「手机传图」→ 显示二维码（一次性 token，30 分钟有效）→ 手机扫码直接打开上传页（**免登录**）→ 传完电脑端自动出现，接着做。
技术上就是"短时 token + 轮询"，不难，但没有一期那个方案省事（一期连二维码都不用）。

> ⚠️ **一个必须提前知道的硬限制**：现在三条视觉接口的请求体上限都是 **4MB**
> （`MAX_BODY = 4 * 1024 * 1024`，因为 Vercel 请求体约 4.5MB）。
> 手机原图经常 3–8MB，**直接传会被 413 拒掉**。所以手机端必须做**前端压缩**
> （长边压到 1600–2000px、JPEG 质量 0.8），压完通常 300–600KB，识别效果反而更稳。
> 这件事一期就要做，不做的话"手机直接拍"会被大图卡死。
